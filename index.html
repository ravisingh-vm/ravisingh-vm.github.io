01 / Application playbooks

What works, by workload.

Each application has a different delivery shape. These playbooks record the practices worth keeping and the next controls to introduce.

API

XML API

Containerized Java service delivered to Azure Container Apps across isolated environments.

  • Build once, promote the same image digest
  • Health-gated revision rollout and fast rollback
  • SAST, SCA and container scanning before release
Desktop

Yield Book AddIn

Windows and Excel-integrated application with a controlled packaging and signing lifecycle.

  • Deterministic build, tests and package signing
  • Versioned artifacts with provenance evidence
  • Ring-based rollout with a recovery package
IaC

Azure Infrastructure

Terraform modules manage application foundations across development and production subscriptions.

  • Remote, locked and versioned state
  • Reviewed plans with policy-as-code checks
  • Protected apply and destroy operations
Operations

Certificate Lifecycle

Automated monitoring and controlled promotion of application certificates and secrets.

  • Vault-backed retrieval with short-lived artifacts
  • Expiry tests and actionable notifications
  • Auditable environment-specific promotion

02 / Delivery roadmap

DevSecOps, in the right order.

Security controls work when they strengthen an understandable delivery path. The sequence starts with trustworthy source and ends with measurable operations.

Target state

Established delivery controls

Prioritize controls that prevent unreviewed or untested changes from reaching production. Progressive delivery follows once the release path is reliable.
